# まとめて進める（答えを先に渡して、1 回で台本と説明図まで）

進め方は 2 つあります。

| 進め方 | 向いているとき | 人が確かめるところ |
|---|---|---|
| 段ごと（[01](01-intake.md)〜[07](07-export.md) の順） | 初めて使う・題材がまだ固まっていない | 各段の終わり（聞き取り・見る人・構成・台本・説明図…） |
| **まとめて**（この頁） | 何を説明するかが決まっていて、資料もそろっている | **最後の報告でまとめて**。MP4 を作る前にもう一度 |

まとめて進めるときは、下の**答えのひな形**を埋めて AI に渡します。AI は聞き取り・見る人・構成の確かめを省き、台本と説明図を書いて、`erkit check`（`--strict` 付き）・`erkit diagram`・`erkit make` の `--dry-run` まで進め、最後に**報告**を返します。

## 変わらない約束

まとめて進めるときも、次の 3 つは変わりません。

1. **区分を最初に決める**。ひな形の 1 行目が区分です。書いていない・`confidential`・分からない、のどれかなら、**AI はほかの欄も資料も読まずに止まります**（クラウドで動く AI の場合。[confidentiality.md](confidentiality.md)）。社外秘を含む材料は、ひな形に貼る前に、この PC の中で動く AI を使ってください
2. **区分を下げるのは人だけ**。AI は `confidential` を `general` に変えません
3. **MP4 を作る前に、人が確かめる**。まとめて進めるのは `--dry-run` まで。`erkit make`（MP4）は、人が報告と確認画像を見て「よい」と言ってから実行します

## 答えのひな形

コピーして埋めます。分からない欄は「分からない」と書けば、AI が決めて報告に挙げます（区分の欄だけは、人が決めて書きます）。

```markdown
## 説明動画の答え（まとめて進める）

- 区分: general            ← 社外秘を含む・分からないなら confidential（その場合、AI は止まる）
- 何を説明するか（1 文）: 窓ガラスを選ぶときに、断熱・日射・結露のどれを優先するかの決め方
- 種別: tool_intro          ← tool_intro（ツールや考え方の紹介）/ work_manual（作業の手順）/ explainer（一般の解説。01-intake の見分け方）
- 題材の id: glass-choice   ← 英小文字・数字・-・_（台本のフォルダの名前になる）
- 見る人と、もう知っていること: 家づくりを考えている人。窓の種類は知らない → A
- 見終わったらできること: 自分の家の方角と地域から、ガラスの種類の候補を 2 つに絞れる
- 資料と根拠: 業界団体の資料（URL）、国の資料（URL）。数値はこの 2 つの範囲だけ
- 撮影: なし                ← あれば、撮るページ（この PC で開ける URL かフォルダ）
- 長さ: 約 2 分（5〜6 シーン）
- そのほか（任意）: 言い回しの好み、使いたい図、入れたくないこと
```

- 資料は、ひな形の下に続けて貼るか、ファイルの場所を書きます
- 数値・規格の番号は、資料のどこにあるかまで書いてあると、報告の「未確認」が減ります

### 解説（explainer）の例

一般の解説なら、種別を `explainer` にします。構成の決まり（問い → しくみ → 比べる・条件 → 選び方・減らし方 → まとめ）と説明図の部品で作られ、撮影はありません。

```markdown
## 説明動画の答え（まとめて進める）

- 区分: general
- 何を説明するか（1 文）: 冬に窓ぎわで足元が寒くなるしくみと、家でできる対策
- 種別: explainer
- 題材の id: cold-draft
- 見る人と、もう知っていること: 家に住んでいる人。窓ぎわが寒いのは知っているが、理由は知らない → A
- 見終わったらできること: 足元が寒くなる順番を説明でき、対策を 1 つ選べる
- 資料と根拠: 公的な資料・業界団体の資料（URL）。確かめられない数値は使わず、未確認にする
- 撮影: なし
- 長さ: 約 2 分（5 シーン）
- そのほか（任意）: しくみはフローの部品で、対策はカードの部品で
```

## AI がすること（エージェントの場合）

1. 区分の欄を読む。`general` 以外なら止まる（上の約束）
2. 欄が足りなければ、**足りない欄だけをまとめて 1 回**聞く。そろっていれば聞かずに進む
3. 台本のフォルダを作る（[04-storyboard.md](04-storyboard.md) の「自分の題材のフォルダを作る」と同じ置き方。種別が `explainer` なら同じ頁の「解説（explainer）のとき」で、解説のひな形から）
4. 見る人・構成を決め（[02](02-audience.md)・[03](03-outline.md) の決まりで）、台本を書く（[04](04-storyboard.md)。**出典の決まり**を守る）
5. 説明図の HTML を書く（[05](05-visuals.md)）。撮影のシーンがあれば操作定義も書く。`explainer` なら部品の見本を写して書き換え、`SOURCES.md` も書く
6. コマンドを順に通す。失敗したら直してもう一度（例はサンプルのパス。AI は自分の台本のパスで実行する）

```powershell
erkit check --strict samples\u-value\u-value.storyboard.md
erkit diagram samples\u-value\u-value.storyboard.md --out output\u-value --overlay output\u-value\check-diagram.png
erkit capture samples\u-value\u-value.storyboard.md --check
erkit make samples\u-value\u-value.storyboard.md --serve samples\u-value\app --dry-run
```

（撮影のシーンが無ければ `erkit capture` と `--serve` は要りません）

7. **ここで止まり、報告を返す**。`erkit make`（MP4）は実行しない

## 報告の形

AI は最後に、次の形で返します。人はこれと確認画像を見て、直すところを伝えるか、MP4 に進みます。

```markdown
## 報告

### 構成
| シーン | 見出し | 画像 | 伝えること | 注釈 |
|---|---|---|---|---|
| intro | … | — | … | — |
| s01 | … | 説明図 | … | … |

### 決めたこと（人が書かなかったので AI が決めた）
- 見る人: A（理由 1 行）
- シーン数・画像の種類・言い回しで迷ったところ

### 根拠が弱い・未確認の数値と事実
| 台本の場所 | 書いたこと | 状態 | 確かめ方 |
|---|---|---|---|
| s02 | ガラスの U 値の目安の範囲 | 資料で確認（資料名・頁） | — |
| s04 | 規格の番号 | **未確認** | 規格の原典を確かめる |

### 確認画像
- 説明図: output\<id>\check-diagram.png（赤枠が指したい部品に重なっているか）

### 通したコマンドと結果
- 台本の検証（check --strict）: OK（区分: general）
- 説明図（diagram）: 6 シーン OK
- 通し生成の段の確認（make --dry-run）: OK（段の順番・出力先・声）

### 次に人がすること
1. 確認画像と台本を見て、直すところを伝える（未確認の項目は人が確かめる）
2. よければ MP4 を作る（AivisSpeech を起動し、PowerPoint は閉じておく）
```

報告の `<id>` には、AI が実際のフォルダ名を入れます。

## 使い方

| 使う AI | 渡し方 |
|---|---|
| Claude Code（プラグイン） | 埋めたひな形を貼って「まとめて進めて」と頼む。`/explainer-reel-kit:explainer-new` の後に貼ってもよい |
| ほかのエージェント | 「`AGENTS.md` と `docs/guide/batch.md` を読んで、まとめて進めて」と頼み、埋めたひな形を貼る |
| チャットだけの AI・手元の LLM | [prompts/05-batch.md](../../prompts/05-batch.md) を貼り、埋めたひな形を続けて貼る。コマンドは人が打つ |

MP4 に進むときは [07-export.md](07-export.md) の手順で（Claude Code なら `/explainer-reel-kit:explainer-make`）。
